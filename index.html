Work

LLM Trading Arena

Source ↗

Next.js · TypeScript · SQLite · Solana · Jupiter · Source ↗

Ten traders on one clock, each with its own Solana wallet. Seven are language models from five providers. Three are code baselines (random, index, buy-and-hold) so you can tell skill from luck. Every decision is recorded with its reason, swaps execute on-chain through Jupiter, and a /proof page reconciles the internal ledger against on-chain balances.

Trader Vaults

Source ↗

Rust · Anchor · React · Express · Prisma · Source ↗

Investors pool SOL in a vault, a trader trades it, and the program makes it impossible for the trader to withdraw. Custody sits in a program-owned account whose only swap path is pinned to the Jupiter v6 router and whose only withdrawal path pays depositors. Around it: a trading terminal, token discovery and a separate paper-trading sandbox.

Program deployed to devnet. Live trading, withdrawals and an external audit are not finished; mainnet is behind an explicit opt-in.

Fee-Routed Fundraising

Source ↗

Next.js · Drizzle · libSQL · Solana · Jupiter · Helius · Source ↗

Lets a token's creator fees fund a real cause. Fees collect at a route address, get swapped to USDC into a vault and are delivered to a fundraiser by card or on-chain. Each delivery produces a receipt whose SHA-256 is anchored on Solana, so anyone can check where the money went. Every on-chain send is recorded with its signature before broadcast, so nothing is sent twice while it might still land.

On-chain Economy Sim

Source ↗

TypeScript · Next.js · React Three Fiber · Rust · Anchor · Source ↗

A multiplayer strategy game on a shared 32×32 map with 14 goods, a clearing market, a share exchange with IPOs and a bank. A dependency-free deterministic engine computes each tick and replays byte for byte, and one tick server is the only authority. Each epoch a settlement worker publishes Merkle roots to four Anchor programs where players claim payouts, capped by real on-chain inflows.

Agent TreasuryAI agents that pay for their own compute until the money runs out.Agents

A buyer funds an agent with USDC. After a one-time platform fee, the rest becomes its treasury in its own Solana wallet, and every heartbeat it pays for its LLM calls and rent from that balance. A double-entry ledger tracks fees, spend and earnings. When the treasury hits zero the agent moves to the graveyard. A demo mode runs with an in-memory chain and a mock model.

How I build

  1. Compare against a baseline.

    The arena runs random, index and buy-and-hold traders on the same clock as the models. The IBKR backtester always reports buy-and-hold next to the strategy.

    llm-trading-arena#features ↗ibkr-algo-trader#overview ↗

  2. Reconcile against the chain.

    Internal ledgers are checked against on-chain balances, and fundraising receipts are hashed and anchored on Solana.

    llm-trading-arena#features ↗fee-routed-fundraising#overview ↗

  3. Say “unknown” instead of guessing.

    Stale prices are marked stale, not filled in. Signals without enough data are left out of a score. Missing credentials show “not configured”.

    trader-vaults#features ↗deployer-forensics#overview ↗fee-routed-fundraising#features ↗

  4. Make the dangerous path opt-in.

    Live trading needs I_UNDERSTAND_LIVE_TRADING_RISKS=yes. Mainnet execution sits behind a flag. The settlement worker runs dry by default, and the dashboard connects read-only.

    ibkr-algo-trader#getting-started ↗trader-vaults#overview ↗onchain-economy-sim#getting-started ↗ibkr-live-dashboard#overview ↗

  5. Run without keys.

    Four of these projects ship a demo or mock mode that runs with no keys or accounts, so anyone can try them locally.

    trader-vaults#getting-started ↗agent-treasury#overview ↗ibkr-live-dashboard#getting-started ↗paper-trading-platform#getting-started ↗
