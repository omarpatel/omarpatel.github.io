Work

LLM Trading Arena

Source ↗

Next.js · TypeScript · SQLite · Solana · Jupiter · Source ↗

Ten traders on one clock, each with its own Solana wallet. Seven are language models from five providers. Three are code baselines (random, index, buy-and-hold) so you can tell skill from luck. Every decision is recorded with its reason, swaps execute on-chain through Jupiter, and a /proof page reconciles the internal ledger against on-chain balances.

Prompt-to-App Platform

Source ↗

TypeScript · Express · BullMQ · Prisma · Postgres · React · E2B · Source ↗

Turns a one-sentence prompt into a hosted web app. Each app is paired with a coin, and the coin's creator fees pay for a Claude agent in an E2B microVM that builds the app, deploys it and keeps working on it. A build only ships after it passes npm run build, a Playwright smoke test and a reviewer model. Generated apps can't contain network or wallet code; they reach the platform only through a small SDK. Every five minutes a reconcile job checks jobs, payouts and the ledger for drift.

Trader Vaults

Source ↗

Rust · Anchor · React · Express · Prisma · Source ↗

Investors pool SOL in a vault, a trader trades it, and the program makes it impossible for the trader to withdraw. Custody sits in a program-owned account whose only swap path is pinned to the Jupiter v6 router and whose only withdrawal path pays depositors. Around it: a trading terminal, token discovery and a separate paper-trading sandbox.

The program is not deployed. Live trading, withdrawals and an external audit are not finished, and mainnet execution needs an explicit opt-in.

Leveraged Treasury Engine

Source ↗

Solidity · Foundry · Uniswap V4 · React · viem · Fastify · Source ↗

Gives a launchpad token its own on-chain treasury. Trading fees are invested in a 3x leveraged vault token, the treasury is marked to market on-chain, and only the gain above cost basis is spent, on buying back and burning the token. Principal is never touched. There are no admin keys: every function is permissionless and every payout address is fixed when the engine is created. If the token goes quiet for 90 days, holders can redeem the treasury pro rata.

Not deployed. The contracts are unaudited, and so are the third-party contracts they depend on.

Fee-Split Vaults

Source ↗

Solidity · Foundry · TypeScript · React · Postgres · Source ↗

A creator-fee vault protocol, and the measurement that said not to launch it. Each token's vault splits every fee between the creator, a promotion budget and the operator, and the contracts and tests are complete. Before deploying, I measured the venue's full 36-day on-chain history. Only 73 fee recipients were winnable against the 109 needed to break even, so the verdict was STOP and it was never deployed.

Fee-Routed Fundraising

Source ↗

Next.js · Drizzle · libSQL · Solana · Jupiter · Helius · Source ↗

Lets a token's creator fees fund a real cause. Fees collect at a route address, get swapped to USDC into a vault and are delivered to a fundraiser by card or on-chain. Each delivery produces a receipt whose SHA-256 is anchored on Solana, so anyone can check where the money went. Every on-chain send is recorded with its signature before broadcast, so nothing is sent twice while it might still land.

How I build

  1. Compare against a baseline.

    The arena runs random, index and buy-and-hold traders on the same clock as the models. The IBKR backtester always reports buy-and-hold next to the strategy.

    llm-trading-arena#features ↗ibkr-algo-trader#overview ↗

  2. Reconcile against the chain.

    Internal ledgers are checked against on-chain and venue balances, and the result is shown on a /proof page. Fundraising receipts are hashed and anchored on Solana.

    llm-trading-arena#features ↗fee-treasury-perps-engine#what-is-in-the-engine ↗fee-routed-fundraising#overview ↗

  3. Measure before launching.

    Fee-Split Vaults was finished and tested, then measured against the venue’s real on-chain history. The numbers said it couldn’t break even, so it was never deployed, and the write-up is in the repo.

    fee-split-vaults-postmortem#the-result ↗

  4. Say “unknown” instead of guessing.

    Stale prices are marked stale, not filled in. Signals without enough data are left out of a score. Missing credentials show “not configured”.

    trader-vaults#features ↗deployer-forensics#overview ↗fee-routed-fundraising#features ↗

  5. Make the dangerous path opt-in.

    Live trading needs I_UNDERSTAND_LIVE_TRADING_RISKS=yes. Mainnet execution sits behind a flag, the settlement worker runs dry by default, and the wallet sweeper only reports until you pass --send and type SWEEP.

    ibkr-algo-trader#getting-started ↗trader-vaults#overview ↗onchain-economy-sim#features ↗hd-wallet-sweeper ↗

  6. Run without keys.

    Many of these projects ship a demo, mock or paper mode that runs with no keys or accounts, so anyone can try them locally.

    agent-treasury#overview ↗ibkr-live-dashboard#features ↗fee-treasury-perps-engine#getting-started ↗fee-split-vaults-postmortem#getting-started ↗
